# XGBoost 入门笔记：是什么、怎么用、怎么用在选股上

> 面向第一次接触 XGBoost 的读者。读完应能回答三个问题：**它是什么**、**怎么跑通一个最小例子**、**拿去预测股票时哪些坑必须先填**。
> 状态：方法整理（2026-10-17），不含本仓库实验结论；训练口径与红线与 [`baseline_plan.md`](baseline_plan.md)、[`kb/`](kb/README.md) 保持一致。

## 0. 三句话版本

1. **XGBoost 是一堆"if-else 小抄"（决策树）排成一队接力改错，最后把所有人的答案加起来打分。**
2. 它最擅长**表格数据**（一行一个样本、一列一个特征）：训练快、对量纲不敏感、自带防过拟合开关。
3. 在股票里它能做的是**把几十个弱因子压成一个横截面排序分**，不是"算出明天涨几个点"。它的上限由数据信噪比决定，而不是由模型本身决定（见 [`kb/xgboost-ceiling.md`](kb/xgboost-ceiling.md)）。

## 1. 它是什么

### 1.1 先看一棵树长什么样

想象给一群人打"熬夜风险分"。你可以写一张问答纸条：

```
睡眠 < 6 小时?
├── 是 → 每天喝咖啡?
│         ├── 是 → 风险 80 分
│         └── 否 → 风险 60 分
└── 否 → 年龄 > 40?
          ├── 是 → 风险 40 分
          └── 否 → 风险 15 分
```

这就是一棵**决策树**：每个分叉是一道判断题（某个特征 ≤ 某个阈值），每个叶子给出一个分数。

- 树太浅（只问一句）→ 什么都学不到（**欠拟合**）。
- 树太深（问到每个人的生日）→ 把训练集里每个人的特殊情况都记住了，换一批人就全错（**过拟合**）。

单棵树的毛病很致命，所以真正干活的从来不是一棵树，而是**一群树**。

### 1.2 一群树有两种组织方式

| | 怎么组队 | 直觉 | 代表 |
|---|---|---|---|
| **Bagging（并行）** | 各自独立看一份随机抽样的数据，最后**投票/取平均** | 请 500 个互不通气的专家，取平均意见 | 随机森林 |
| **Boosting（串行）** | 一棵接一棵，**每棵专门去修前面所有树的错**，最后**加权相加** | 一个学生做题，每轮只订正上一轮的错题 | **XGBoost**、LightGBM、CatBoost |

XGBoost 属于第二类：**梯度提升树（Gradient Boosting Decision Tree, GBDT）** 的一个工程实现。GBDT 的思想来自 Friedman 2001，XGBoost 是陈天奇等人在 2016 年给出的更高效、带正则的版本。

### 1.3 "提升（Boosting）"到底在干什么

用一个打分场景说清楚。假设要预测一个人明年的医疗花费：

1. **第 1 棵树**：什么都不知道，所有人先给一个平均值，比如 5000 元。
2. **算误差**：有人实际花了 8000，误差 +3000；有人花了 3000，误差 −2000。
3. **第 2 棵树**：不再预测"花多少钱"，而是去预测**"第 1 棵树错在哪"**（那 ±3000 的残差），用年龄、BMI 这些特征去解释误差。
4. **第 3 棵树**：再去修"前两棵树加起来还剩下的错"。
5. 重复几百轮，最后 **预测值 = 所有树的输出之和**。

一句话：**每棵新树都在拟合"当前模型还错多少"，然后只迈一小步。**

那个"一小步"就是**学习率（learning_rate / eta）**：每棵树的输出都会乘上它再加进总分。学习率小 → 每步走得更谨慎、需要更多树、通常更稳；学习率大 → 学得快但容易冲过头。

写成一行公式（唯一需要记的一个）：

```
ŷ(x) = Σ f_k(x)        f_t 拟合的是当前损失函数对预测值的负梯度（≈残差）
```

XGBoost 的"Gradient"就来自这里：它用梯度下降的思路一棵一棵地逼近目标，而不是一次性求解。

### 1.4 "X" 是什么：工程上的"极限"

XGBoost 全名 e**X**treme **G**radient **B**oosting，那个 X 指的是把 GBDT 做到了工程极限。具体加了这些料：

| 特性 | 解决什么问题 | 对使用者意味着什么 |
|---|---|---|
| **显式正则项** | 惩罚"叶子太多、叶子分数太极端" | `reg_lambda` / `reg_alpha` / `max_depth` 能直接压过拟合 |
| **二阶导数（牛顿法）** | 只知道方向不够，还知道曲率 | 同样效果通常需要更少的树 |
| **列块 + 直方图** | 逐列预排序很慢 | `tree_method="hist"` 在百万行上也能几分钟训完 |
| **稀疏/缺失值自动处理** | 真实数据总有空值 | 不用手工填 0，它会学"缺失走左边还是右边" |
| **支持自定义损失** | 业务目标不一定是 MSE | 可以写 IC 损失、排序损失、分位数损失 |
| **早停、单调约束、交叉验证** | 训练过程可控 | 有 `early_stopping_rounds`、`monotone_constraints` |

> 一句提醒：这些是"工程优势"，不是"预测优势"。同样的问题换成 LightGBM 通常差不了多少，换成线性模型也不一定差很多——**模型的边际收益远小于特征和标签的边际收益**。

### 1.5 和其他模型比一比

| 模型 | 擅长 | 短板 | 什么时候选它 |
|---|---|---|---|
| 线性 / 岭回归 | 可解释、极稳、小样本 | 抓不到交互（"低估值 + 高动量"这种组合条件） | 永远先做一个当基线 |
| 随机森林 | 几乎不用调参、抗过拟合 | 精度通常略逊、不擅长外推 | 想快速确认"特征里到底有没有信号" |
| **XGBoost / LightGBM** | 表格数据精度高、快、能处理缺失 | 容易过拟合、黑箱、不能外推 | **表格特征 + 中等数据量的默认选择** |
| LSTM / GRU | 原生建模时间顺序 | 吃数据、慢、对特征工程敏感 | 数据量足够大（十万级以上样本）才值得试 |
| Transformer / 时序基础模型 | 长依赖、可预训练 | 训练成本高、小数据上未必赢 | 研究前沿，不是第一版该碰的 |

### 1.6 它明确不擅长什么（很重要）

1. **不能外推**。树的本质是"分段常数"：训练集里收益最高只见过 +9.9%，那遇到 +15% 的行情它最多也只能输出边界值。线性模型能顺着斜率往外走，树不能。
2. **不原生懂顺序**。它不知道"第 3 行在第 4 行之前"，时间信息必须你自己做成特征（滞后、滚动、差分）。
3. **不原生懂结构**。图关系（产业链、股东关联）和文本（公告、新闻）都得先变成数值特征。
4. **信噪比低时会疯狂背答案**。这一点在金融数据上是常态，见第 5 节。

## 2. 常见功能（API 地图）

### 2.1 两种用法：sklearn 风格 vs 原生 API

| | sklearn 风格（`XGBClassifier` / `XGBRegressor`） | 原生 API（`xgb.train` + `DMatrix`） |
|---|---|---|
| 上手难度 | 低，和 sklearn 完全一致 | 中，需要自己管 DMatrix 和轮数 |

| 早停写法 | 构造函数里 `early_stopping_rounds=` + `eval_set` | `xgb.train(..., early_stopping_rounds=)` |
| 建议 | **先用这个** | 卡住了再下沉 |

### 2.2 任务目标（`objective`）对照表

| 你想做什么 | objective | 常用指标 | 输出 |
|---|---|---|---|
| 预测一个数值（收益率、波动率） | `reg:squarederror` | `rmse`、`mae` | 点估计 |
| 二分类（明天涨/跌、跑赢/跑输） | `binary:logistic` | `auc`、`logloss` | 概率 |
| 多分类（大涨/小动/大跌） | `multi:softprob` | `mlogloss`、`merror` | 各类概率 |
| 排序（同一天内给股票排名） | `rank:pairwise` / `rank:ndcg`（需 `qid` 分组） | `ndcg`、`map` | 排序分 |
| 给区间（预测 10%/50%/90% 分位） | `reg:quantileerror` + `quantile_alpha` | `quantile` loss | 每个分位一个模型 |
| 计数（成交笔数等） | `count:poisson` | `poisson-nloglik` | 期望计数 |

> 做"涨跌幅 + 可信区间"（[`baseline_plan.md`](baseline_plan.md) 的形态 B），标准做法是**训练三个分位模型**（α=0.1/0.5/0.9），再用覆盖率检验区间是否可信。

### 2.3 参数：新手只需要先记住 6 个

| 参数 | 作用 | 典型起点 | 调大的后果 |
|---|---|---|---|
| `n_estimators` | 树的数量（迭代轮数） | 300~2000 + 早停 | 过多 → 过拟合 |
| `learning_rate`（eta） | 每棵树走多大一步 | 0.01~0.05 | 过大 → 不稳、跳过最优点 |
| `max_depth` | 每棵树最深几层 | **3~6** | 过深 → 记住噪声 |
| `min_child_weight` | 叶子最少要多少样本（hessian 和） | 金融数据建议 **50~200** | 过小 → 叶子太碎 |
| `subsample` / `colsample_bytree` | 每棵树用多少行 / 多少列 | 0.6~0.9 | 过大 → 树之间太像 |
| `reg_lambda` / `reg_alpha` | L2 / L1 正则 | 1.0 / 0 | 过大 → 学不动 |

其余参数（`gamma`、`max_delta_step`、`scale_pos_weight`、`tree_method`、`n_jobs`）等遇到具体问题再查。**调参顺序建议**：先固定 `learning_rate=0.05` + 早停定 `n_estimators` → 再调 `max_depth` / `min_child_weight` → 最后才动采样和正则。

> 金融数据上有一条硬经验：**树深 3~6、叶子样本量上百**，这不是保守，是必需。券商实践里常见"树深 3、树数 50"的极简配置。

### 2.4 最小可运行例子（二分类，带早停）

```python
import numpy as np
import pandas as pd
from sklearn.metrics import roc_auc_score
from xgboost import XGBClassifier

# X_train / X_valid / X_test: DataFrame，列名即特征名
# y_*: 0/1 标签
model = XGBClassifier(
    n_estimators=2000,
    learning_rate=0.03,
    max_depth=4,
    min_child_weight=100,
    subsample=0.8,
    colsample_bytree=0.8,
    reg_lambda=1.0,
    objective="binary:logistic",
    eval_metric="auc",
    tree_method="hist",
    early_stopping_rounds=50,   # 验证集 50 轮不涨就停
    random_state=42,
)

model.fit(
    X_train, y_train,
    eval_set=[(X_valid, y_valid)],
    verbose=False,
)

print("最佳迭代轮数:", model.best_iteration)
proba = model.predict_proba(X_test)[:, 1]
print("样本外 AUC:", roc_auc_score(y_test, proba))

# 只用最佳轮数重新打分（避免用到早停之后多训的树）
proba = model.predict_proba(X_test, iteration_range=(0, model.best_iteration + 1))[:, 1]
```

原生 API 的等价写法（需要自定义损失或多验证集时用）：

```python
import xgboost as xgb

params = {
    "objective": "binary:logistic",
    "eval_metric": ["auc", "logloss"],
    "eta": 0.03, "max_depth": 4, "min_child_weight": 100,
    "subsample": 0.8, "colsample_bytree": 0.8, "lambda": 1.0,
    "tree_method": "hist", "seed": 42,
}
dtrain = xgb.DMatrix(X_train, label=y_train, feature_names=list(X_train.columns))
dvalid = xgb.DMatrix(X_valid, label=y_valid, feature_names=list(X_valid.columns))
dtest = xgb.DMatrix(X_test, feature_names=list(X_test.columns))

booster = xgb.train(
    params, dtrain,
    num_boost_round=2000,
    evals=[(dtrain, "train"), (dvalid, "valid")],
    early_stopping_rounds=50,
    verbose_eval=200,
)
proba = booster.predict(dtest, iteration_range=(0, booster.best_iteration + 1))
```

### 2.5 早停（early stopping）为什么必须有

没有早停，你不知道该训多少轮；有了早停，"训多少轮"变成一个由验证集自动决定的问题。

三个必须注意的点：

- 早停用的验证集必须是**时间上靠后**的数据，不能是随机切出来的一块。
- 早停只负责"停"，不负责"调参"；别反复用同一个验证集试几百组参数，那等于把验证集变成了训练集（见 5.4）。
- 打分时用 `iteration_range` 截断到 `best_iteration`，否则会用到早停后多训的树。

### 2.6 特征重要性：三种口径 + 一个警告

```python
booster = model.get_booster()
gain  = booster.get_score(importance_type="gain")    # 该特征带来的平均增益（最常用）
cover = booster.get_score(importance_type="cover")   # 该特征覆盖的样本量
weight = booster.get_score(importance_type="weight") # 被用作分裂点的次数
```

**警告：`model.feature_importances_`（默认 MDI，靠不纯度下降算）会骗人。**

- 系统性偏向**高基数/连续特征**（可切的分点多，蒙也能降不纯度）。
- 特征之间高度相关时，重要性会在相关组里**随机分配**，看起来每个都不重要。
- 而且它是**样本内**算的，天然乐观。

更可靠的两个替代：

```python
# 1) 样本外置换重要性：把某一列打乱，看样本外指标掉多少
from sklearn.inspection import permutation_importance
pi = permutation_importance(model, X_test, y_test, n_repeats=20, random_state=42)

# 2) SHAP：给出每个样本、每个特征的加性贡献
import shap
explainer = shap.TreeExplainer(model)
sv = explainer.shap_values(X_test)
shap.summary_plot(sv, X_test)
```

即便如此也别全信：有研究指出 SHAP 与"直接删掉这个特征再测"的结论一致性只有中等水平。**结论要两种方法交叉验证**，最后用"删掉重训、看样本外是否变差"来定论。

### 2.7 缺失值与类别特征

- **缺失值**：留 `np.nan` 不要填 0。XGBoost 会为每个分裂点学一个默认方向（`missing=` 参数默认 `nan`）。
  - 但"缺失"和"真实的 0"是两件事：停牌日不是"成交额为 0"。语义上要分开，宁可用一个 `is_suspended` 标记列。
- **类别特征**：一列股票代码、行业名这类，要么 one-hot，要么用 `enable_categorical=True`（需要 pandas `category` dtype）。**但代码本身通常不该进模型**——它没有可泛化含义，容易变成"背某只股票的历史"。

## 3. 整体训练使用流程（七步）

```
  ① 定义问题            ② 准备数据            ③ 造特征 / 造标签
  预测什么？怎么用？  →  从哪来？什么口径？  →  只用 T 日及之前的信息
        │                     │                      │
        └─────────────────────┴──────────────────────┘
                              ↓
  ⑦ 上线与滚动重训  ←  ⑥ 评估（预测质量 + 扣成本收益）  ←  ⑤ 训练 + 早停
        ↑                                                   ↑
        └──────────────  ④ 时间顺序切分（训练/验证/测试）─────┘
```

### ① 定义问题：先写清楚"预测什么、错了会怎样"

必须回答四件事，答不清就别写代码：

- **预测对象**：单只股票？还是每天全市场几百只一起排序？
- **预测目标**：涨/跌（分类）、涨跌幅（回归）、还是"未来 N 日收益的分位"？
- **预测时点**：什么时候能用上这条预测？信号在哪天产生、哪天成交？
- **成功标准**：AUC 到多少算有用？还是扣掉成本后年化超额 > 0？

> 新手最常犯的错：直接写 `model.fit(X, y)`，然后才发现"标签用的是收盘价、特征里混了当天的收盘价"，一路白干。

### ② 准备数据：口径比数量重要

- 数据源、拉取时间、复权方式（前复权/后复权/不复权）必须记录。
- **前复权有陷阱**：用"最新复权因子"回看历史，等于让历史价格知道了未来（见 5.1）。
- 停牌、涨跌停、ST、退市都要有标记，不能悄悄丢掉。

### ③ 造特征 / 造标签：这是决定上限的一步

- 特征：**任何在 T 日收盘时点还不可知的东西都不能进**。滚动窗口要"左闭"，用 `shift(1)` 兜底检查。
- 标签：口径必须与交易口径一致（T 收盘出信号、T+1 开盘成交，就按这个口径算收益）。
- 先做 5~20 个有经济含义的特征，比一上来堆 300 个强。**特征越多，噪声越多，过拟合越必然。**

### ④ 切分：只能用时间切

```python
# 正确：按时间切
train = df[df["date"] <  "2020-01-01"]
valid = df[(df["date"] >= "2020-01-01") & (df["date"] < "2021-01-01")]
test  = df[df["date"] >= "2021-01-01"]
```

- **禁止** `train_test_split(shuffle=True)` 和随机 K 折：那是让模型偷看未来。
- 验证集只用来早停和选阈值；**测试集最后只碰一次**。
- 更接近真实使用的方式是**滚动（walk-forward）**：每往前走一段就重训一次，永远保证"训练截止日 < 预测日"。

### ⑤ 训练 + 早停

固定随机种子，先跑一个"默认参数 + 早停"的版本当基线，再考虑调参。

### ⑥ 评估：两层，缺一不可

| 层 | 看什么 | 为什么 |
|---|---|---|
| 预测质量 | AUC、准确率、RankIC、分层单调性、区间覆盖率 | 判断模型到底有没有学到东西 |
| 交易质量 | 扣成本后的收益、最大回撤、换手率、胜率 | **最终标准**：准确率涨了但扣成本不赚钱，等于没用 |

必须对比的基线：**随机猜**、"昨天涨今天也涨"这类朴素规则、以及**一个简单的线性模型**。

### ⑦ 上线与滚动重训

- 每次重训产出一个可追溯的模型版本（数据截止日 + 参数 + 版本号）。
- 监控衰减：一旦样本外 IC 连续几个月下滑，先怀疑市场结构变了，而不是先去调参。

### 三条心法

1. **先跑通，再调优**。一个默认参数的完整管线，价值远大于一个调了 500 组的半成品。
2. **先基线，再加复杂度**。如果 500 个特征的 XGBoost 只比 10 个因子的线性模型好一点点，那点提升大概率是噪声。
3. **先防泄漏，再谈精度**。泄漏能让任何模型看起来像神。

## 4. 用在股票预测上

### 4.1 两种范式，先选对

| | 范式 A：单只股票的时间序列 | 范式 B：全市场横截面（主流） |
|---|---|---|
| 样本怎么来 | 一只股票的每一天是一行 | 每一天的每只股票是一行 |
| 样本量 | 10 年日线 ≈ 2400 行（**太少**） | 500 只 × 2400 天 ≈ 120 万行 |
| 学的是什么 | "这只股票明天涨不涨" | "今天哪些股票比其他股票更可能涨" |
| 天生缺陷 | 样本少、噪声大、换个市场就失效 | 需要处理截面相关性、行业/风格暴露 |
| 适合 | 验证管线、教学 | 真正做策略 |

**结论：想做能用的东西，走范式 B。** 范式 A 只适合先把管线跑通、把泄漏和成本检查做对。
本项目的 [`baseline_plan.md`](baseline_plan.md) 就是"先用少量标的把形态 A 跑通，再扩展到更大股票池"的路线。

范式 B 的核心技巧是**标签做截面标准化**：不预测"涨 3%"，而预测"今天在所有股票里排前 30%"。

```python
# 每天单独排名，消除"今天大盘普涨"的干扰（beta）
df["y_rank"] = df.groupby("date")["fwd_ret_1"].rank(pct=True)
df["y_bin"]  = (df["y_rank"] > 0.5).astype(int)   # 跑赢当日中位数 = 1
```

### 4.2 落地要定死的六件事

| 项 | 建议 | 本项目的对应约定 |
|---|---|---|
| **目标** | 先二分类（跑赢/跑输同日中位数），再升级到分位数区间 | 形态 A → 形态 B |
| **标签** | T 日收盘出信号、T+1 开盘买入、按同一口径算收益 | `NextOpen` 成交 |
| **特征** | 只用 T 日及之前；量价 + 流动性 + 波动，先不加基本面 | 见 4.3 |
| **切分** | 时间顺序 + walk-forward，测试期严格在训练期之后 | [`baseline_plan.md`](baseline_plan.md) 第 3 节 |
| **评价** | 预测质量（AUC / RankIC）+ 扣成本收益，两层都报 | 同上第 1 节 |
| **执行** | T+1、涨跌停不可成交、停牌不产生样本、成本滑点进回测 | [`kb/backtest-and-leakage-redlines.md`](kb/backtest-and-leakage-redlines.md) |

### 4.3 特征清单（第一版够用）

| 类别 | 例子 | 注意 |
|---|---|---|
| 动量/反转 | 5/20/60 日收益率、距 N 日新高距离 | 都要 `shift(1)` 后再滚动 |
| 波动 | 20 日收益率标准差、ATR、日内振幅（高-低） | 波动比收益好预测得多 |
| 流动性 | 20 日平均换手率、成交额分位、量比 | A 股里流动性类因子权重最高，但也最吃成本 |
| 量价结构 | 均线乖离、量价相关性、放量突破 | 别用"未来 N 日最高价"这种特征 |
| 市场状态 | 指数当日涨跌、市场宽度、行业相对强弱 | 用来做条件分层，不是用来预测大盘 |
| 板型/可交易性 | 是否涨停、是否一字板、是否停牌 | 既是特征，也是**样本过滤条件** |
| 基本面（后期） | PE/PB 分位、ROE、营收增速 | **必须按公告日对齐**，不能按报告期 |

### 4.4 代码骨架（横截面 + 时间切分）

```python
import numpy as np
import pandas as pd
from xgboost import XGBClassifier

FEATURES = ["ret_5", "ret_20", "vol_20", "turnover_20", "bias_20", "amt_ratio_5"]
LABEL = "fwd_ret_1"      # T+1 开盘买入 → 收盘，口径与交易一致

df = df.sort_values(["date", "code"]).reset_index(drop=True)

# 1) 标签截面标准化：只比"同日谁更强"，不比"今天大盘涨多少"
df["y_rank"] = df.groupby("date")[LABEL].rank(pct=True)
df["y_bin"] = (df["y_rank"] > 0.5).astype(int)

# 2) 过滤不可交易样本（涨停买不进 / 停牌 / 流动性不足）
tradable = (~df["is_limit_up"]) & (~df["is_suspended"]) & (df["amount_20"] > 2e7)
df = df[tradable].copy()

# 3) 时间顺序切分
train = df[df["date"] < "2021-01-01"]
valid = df[(df["date"] >= "2021-01-01") & (df["date"] < "2022-01-01")]
test = df[df["date"] >= "2022-01-01"]

model = XGBClassifier(
    n_estimators=1000, learning_rate=0.03, max_depth=4,
    min_child_weight=100, subsample=0.8, colsample_bytree=0.8,
    reg_lambda=1.0, objective="binary:logistic", eval_metric="auc",
    tree_method="hist", early_stopping_rounds=50, random_state=42,
)
model.fit(train[FEATURES], train["y_bin"],
          eval_set=[(valid[FEATURES], valid["y_bin"])], verbose=False)

# 4) 按天算 RankIC：每天预测排序 vs 实际收益排序的相关系数
test = test.assign(pred=model.predict_proba(test[FEATURES])[:, 1])
ic = test.groupby("date").apply(
    lambda g: g["pred"].corr(g[LABEL], method="spearman"), include_groups=False
)
print(f"日均 RankIC={ic.mean():.4f}  ICIR={ic.mean() / ic.std():.3f}")
```

看结果时的三个习惯：

- **看 IC 的均值，也看它的稳定性**（ICIR = 均值/标准差）。均值 0.04 但每天正负乱跳，等于没有。
- **看分层单调性**：按预测分分 5 组，看各组实际收益是不是单调排列。不单调说明模型在抓噪声。
- **一定要看扣成本后的结果**。RankIC 0.03 的策略换手可能极高，成本一扣就归零。

### 4.5 从分数到交易动作

```
模型输出概率 p
  ├─ p > 上阈值  → 次日开盘买入（先检查：涨停？停牌？流动性够吗？）
  ├─ p < 下阈值  → 卖出/不买
  └─ 中间区间    → 不动（空仓也是一种仓位）
```

- 阈值在**验证集**上选，绝不在测试集上选。
- 每笔交易的成本（佣金 + 印花税 + 过户费 + 滑点）必须进回测，否则收益是纸面上的。
- 组合层面还要看：持仓集中度、行业暴露、最大回撤。单票 AUC 好看不代表组合能活。

## 5. 必须解决的问题（分五层）

### 5.1 数据层

| 问题 | 症状 | 处理办法 |
|---|---|---|
| **复权因子前视** | 前复权价用"最新因子"回看历史，历史价格偷看了未来 | 用后复权或点位还原；把复权口径写进报告 |
| **停牌当 0 处理** | 停牌日收益算成 0%，拉低波动率、制造假信号 | 停牌日标记 + 剔除，绝不填 0 |
| **涨跌停不可成交** | 回测里买到一堆开盘涨停的股票，收益虚高 | 标签层和执行层各过滤一次 |
| **幸存者偏差** | 只用"现在还在上市"的股票回测 | 用含退市股的完整历史股票池 |
| **财务数据时点错位** | 用 Q1 数据在 4 月 1 日就交易，但公告 4 月 28 日才发 | 一律按**公告日**对齐，不按报告期 |
| **缺失与 0 不分** | 把"没数据"和"数值为 0"混为一谈 | 单独加 `is_missing` 标记列 |

### 5.2 标签层

| 问题 | 说明 | 处理办法 |
|---|---|---|
| **标签与交易口径不一致** | 用收盘→收盘算标签，却按开盘价成交 | 标签、回测、评估三处用同一个口径 |
| **标签重叠** | 预测"未来 5 日收益"时，相邻两天的标签共享 4 天，样本不独立 | 加大持有期间隔，或用重叠感知的样本权重 |
| **类别极不平衡** | "大涨 > 3%" 只占 5%，模型学会永远猜 0，准确率 95% 却毫无用处 | 用 `scale_pos_weight`、改评价指标（AUC/RankIC），别用准确率 |
| **涨跌停样本污染标签** | 一字涨停当天的"次日收益"不可实现 | 在标签构造阶段就剔除 |

### 5.3 模型层

| 问题 | 症状 | 处理办法 |
|---|---|---|
| **过拟合（必然，不是可能）** | 样本内 AUC 0.75，样本外 0.51 | 树深 3~6、叶子样本 100+、行列采样、早停、减少特征数 |
| **非平稳 / 状态漂移** | 换个市场阶段就失效 | 滚动重训、只用近 N 年数据、分状态建模 |
| **无外推能力** | 极端行情只输出历史边界值 | 接受它；极端行情靠风控而非模型 |
| **特征重要性误导** | 随机噪声因子的重要性排进前十 | 用样本外置换重要性 + SHAP + 删掉重训，三法交叉 |
| **把风格暴露当 alpha** | 超额其实来自小市值/动量暴露 | 事前风格中性约束 + 事后归因拆解 |
| **多重检验** | 试了 500 组参数选最好的，样本外其实是样本内 | 记录试验次数；对最优结果打折看 |

### 5.4 评估层

| 问题 | 症状 | 处理办法 |
|---|---|---|
| **随机切分泄漏** | 随机 K 折让未来样本进入训练 | 只做时间切分 + walk-forward |
| **相邻样本泄漏** | 训练集最后一天和测试集第一天标签窗口重叠 | Purged & Embargoed CV（切分处删掉一段缓冲） |
| **用准确率当唯一指标** | 52% 准确率可以很赚，60% 可以很亏 | 看 AUC、RankIC、分层收益、扣成本收益 |
| **只报最好的那次** | 复现不出来 | 固定种子、记录数据版本、报告全部分布而非单点 |
| **忽略成本** | 换手 100%+/月的策略毛超额 16%，净超额可能只剩 11% | 成本进回测；同时报换手率和成本占比 |

### 5.5 工程层

| 问题 | 处理办法 |
|---|---|
| **不可复现** | 保存数据截止日、特征列表、参数、种子、库版本；一个模型一个目录 |
| **训练/预测口径漂移** | 特征计算代码训练和推理共用同一份，不要各写一遍 |
| **衰减无人监控** | 定期算样本外 IC，画时间序列；连续下滑就重训或下线 |

## 6. 现实预期：别被"高准确率"骗了

以下量级来自公开研究与券商研报的检索整理（**非本仓库验证结论，引用需核实原文**）：

| 指标 | 现实量级 | 含义 |
|---|---|---|
| 方向分类 AUC | 约 0.52~0.56 | 只比抛硬币好一点点；**声称 0.7+ 基本是泄漏或过拟合** |
| 方向准确率 | 约 52%~55% | 长期稳定 >55% 且扣成本盈利，已优于多数公开研究 |
| 日频截面 RankIC | 0.03~0.06 属顶级，0.01~0.03 是普通水平 | 0.05 常被当作"有意义的 alpha"经验门槛 |
| 单股日收益 R² | 通常 < 0.01 | 别指望"解释方差" |
| 波动率 / 区间预测 | RankIC 0.5+ 量级 | 波动率远比收益可预测 → **区间比点位靠谱** |
| A 股成本门槛 | 方向准确率需 > 约 52%~55%（随换手变化）才能覆盖 T+1 + 印花税 + 滑点 | 不扣成本的结果没有意义 |

补充两条检索到的结构性结论：

- **分类通常优于回归**。中金（2024-10，沪深300 内测试）报告 XGBoost 分类模型年化超额约 6.7%，回归模型仅约 0.9%，"几乎没有差异"。这本质是：**猜涨跌幅很难，按相对强弱排序相对可行**。
- **超额在衰减**。同一批价量因子 + 树模型的框架，2016–2021 年在中证 500/1000 增配上能做出两位数年化超额，代价是月均双边换手 100%+；随着因子拥挤度上升，这套框架近年的边际收益明显收窄。

> 溯源：Leippold, Wang & Zhou, *Machine Learning in the Chinese Stock Market*, JFE 2022；Han 等, arXiv:2606.12843（AUC 0.547、Rank IC 0.119）；中金《XGBoost 因子筛选与合成的指数增强应用》2024-10；广发金工《机器学习选股训练手册》2025-06；检索日期 2026-10-17。
> 验证状态：**均为检索转述，未独立复现**。本仓库自己的量级要等 [`baseline_plan.md`](baseline_plan.md) 跑出结果后再写进 [`kb/`](kb/README.md)。

## 附录 A：术语速查

| 术语 | 一句话解释 |
|---|---|
| 决策树 | 一串 if-else 判断题，叶子给出预测值 |
| 集成（ensemble） | 把很多模型的结果合起来用 |
| Bagging | 并行训练、互不干扰、最后平均（随机森林） |
| Boosting | 串行训练、每棵修前面的错、最后相加（XGBoost） |
| 残差 | 真实值 − 当前预测值 |
| 学习率（eta） | 每棵树贡献打几折，越小越稳越慢 |
| 早停 | 验证集指标不再提升就停止训练 |
| 过拟合 | 把训练集的噪声也学会了，换个数据就崩 |
| 前视偏差 / 泄漏 | 训练时用到了当时不可能知道的信息 |
| walk-forward | 滚动向前：每段时间重训、只用历史、预测未来 |
| Purged CV | 切分处删掉一段样本，防止标签窗口跨边界泄漏 |
| IC / RankIC | 预测值与实际收益的相关系数（Rank 版用排名算） |
| ICIR | IC 均值 / IC 标准差，衡量稳定性 |
| MDI | 基于不纯度下降的特征重要性，有偏 |
| SHAP | 把预测值拆成各特征的加性贡献 |
| 分位数回归 | 直接预测"10%/50%/90% 分位"，用来给区间 |

## 附录 B：一页速查

```
是什么   一堆浅决策树串行接力纠错，加总打分
擅长     表格数据、非线性、特征交互、缺失值
不擅长   外推、时序、图、文本原始形态、低信噪比场景
最小用法 XGBClassifier(...).fit(X, y, eval_set=[(Xv, yv)])
必调参数 n_estimators(早停) / learning_rate / max_depth / min_child_weight
必有步骤 时间切分 → 早停 → 两层评估（预测质量 + 扣成本收益）
股票用法 截面排序（每天比强弱），不是猜点位
必防坑   泄漏（复权/财务时点/随机切分）、过拟合、成本、特征重要性误导
```
